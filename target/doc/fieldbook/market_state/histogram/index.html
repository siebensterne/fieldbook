Module histogram 

Source
Expand description

Fixed-bucket latency histograms for stage-specific performance evidence.

Each boundary owns one Histogram of atomic bucket counters. Sampling is allocation-free: Histogram::record reads a monotonic Instant elapsed value, maps it to a fixed boundary with a bit-length calculation, and bumps one counter. The histogram is shared by every worker that crosses the same boundary, so there is exactly one set of raw counts to report.

Percentiles are nearest-rank estimates derived from the merged bucket counts, never averages of per-worker percentiles. A bucket represents the half-open interval (previous_bound, bound], so a reported percentile is the inclusive upper bound of the bucket containing that rank. This is a deliberate accuracy trade: compact, deterministic, mergeable counts instead of a claim of exact ordering or nanosecond precision. The final bucket is open-ended (overflow) and is represented by the observed maximum.

Nanoseconds are the storage unit, not a precision claim. The clock’s step (measured per host in the stress manifest as clock_resolution_ns) can be far coarser than a nanosecond, and scheduling or instrumentation overhead can be far larger than the step. See docs/PERFORMANCE_METHODOLOGY.md.

Allocation-free, lock-free fixed-bucket histogram. Safe to share across threads via Arc; all counters use relaxed atomics because timing samples are evidence, not synchronization.

All measured stage boundaries for one run. Shared by the core, writer, journal, and report so a single set of raw counts is published.

Histograms owned by the serialized writer thread. The coordinator creates these once and shares the same counters with the writer and the report.

Functions§

bucket_index
Map a duration in nanoseconds to a fixed bucket in constant time without allocation. Buckets 1 through 33 cover values above the preceding power of two and at or below the corresponding power. Bucket 0 covers [0, 1]; the final bucket records overflow.
