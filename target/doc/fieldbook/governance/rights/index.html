Module rights 

Source
Expand description

Machine-readable data rights and entitlement decisions.

Authorization is scoped to a declared actor, a typed lifecycle operation, a typed data object (kind, identity and version), a named recipient identity and recipient class, a licensee, a provider, a source product, a venue, a segment, an instrument/field/modality/time window, a territory, a delivery method, a purpose, a retention rule and an effective interval. A dataset name or an object kind alone never carries permission. Access to a feed does not grant storage, derived-data use or redistribution rights.

Every decision is recorded with its licence reference, document digest, contract revision and recording time. Ambiguous, conflicting or revoked authorizations fail closed.

§Audit commit boundary

An audit acknowledgement means one JSON file containing the decision has been written to a sibling temporary file, its bytes fsynced, the file renamed into the audit directory and the parent directory fsynced (see crate::report::write_bytes_atomic). It is a durability acknowledgement for the decision record only. It does not mean a provider was contacted, that the operation succeeded, or that the underlying licence is valid. A permitted decision is written before the network side effect; a write failure prevents that side effect. A denied decision is written when possible, but an audit failure never converts a denial into a permission. Audit records carry only scalar identifiers and counts: no credentials, proxy URLs, headers or raw payloads are ever included.
