Expand description

A batch of normalized events decoded from one websocket payload.

Fields§

§events: Vec<ExchangeEvent>§bytes: usize§raw: Option<RawFrame>

Exact payload, retained for the raw-frame journal. Native transport control frames carry no application payload and leave this empty.

§decode: DecodeOutcome§received_at_us: Option<i64>§signal: SessionSignal

What kind of observation this frame carries, typed at the adapter or transport boundary. Never inferred from an empty event list.

§mechanism: HeartbeatMechanism

The venue’s heartbeat mechanism, assigned by the adapter.

§observations: Vec<TransportObservation>

Every observation retained for this read, in worker observation order: the inbound data frame, or the native control exchange (inbound Ping followed by the outbound Pong response).

§transport_failure: Option<String>

Set when an inbound control frame was observed but the outbound response could not be sent. The worker journals the evidence first and then treats the connection as unusable.

pub fn heartbeat_ack(correlation: Option<Vec<u8>>) -> Self

A native heartbeat acknowledgement as a control observation. Used by session-level tests and adapters that model a PONG without a data payload.

Source

pub fn native_control( payload: WsPayload, response: Option<WsResponse>, mechanism: HeartbeatMechanism, pong_signal: SessionSignal, received_at_us: i64, ) -> Self

Build a frame for a native WebSocket control read, preserving the inbound evidence and (for a peer Ping) the outbound Pong result.

pong_signal is the venue’s interpretation of an inbound native Pong: HeartbeatAck where native Pong acknowledges a client heartbeat, ProtocolControl where it does not.
