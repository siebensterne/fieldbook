Module journal 

Source
Expand description

Append-only journal for raw public market-data frames.

The journal preserves the exact bytes read from a public websocket before normalization, including frames the decoder rejects. It is independent of the SBE capture: the SBE schema and its on-disk representation are unchanged.

§Durability states

A record advances through observable stages:

  • queued — accepted into the bounded channel owned by the writer thread;
  • written — handed to the operating system file buffer;
  • flushed — removed from the process buffer with std::io::Write::flush;
  • synced — persisted with std::fs::File::sync_all;
  • finalized — covered by a segment footer and a manifest entry after the partial file was renamed.

A record reported as written is not durable across a process or host failure. The manifest names the configured policy, and the final run state distinguishes a completed capture from an interrupted one.

§File layout

A run directory contains manifest.json and numbered segment files. A segment is created as <index>.pmj.partial, receives a header, records, and a footer, then is synced and renamed to <index>.pmj. The manifest is rewritten through the atomic JSON helper after each finalized segment and at shutdown. A crash can leave a partial segment and an open manifest, but verification reports that state instead of treating it as complete.

Segment header and footer contain a SHA-256 checksum. Every record carries a checksum trailer over its framing, JSON header, and payload. Verification recomputes every checksum, rejects truncated records, and compares the footer and manifest counts, byte ranges, timestamps, and sequence ranges.

§Backpressure

The caller blocks on a full queue for enqueue_timeout. Exceeding that deadline marks the run failed and returns an error. Write, flush, sync, or rename failures follow the same rule: the writer stops, the status becomes failed, and shutdown returns an error.
