Module ndc_release 

Source
Expand description

NDC v2 release producer under WS-NDC-2026-11-24-002 Profile 1.

This module builds a complete canonical manifest, its RFC 8785 JCS byte sequence, the detached Ed25519 sidecar and the ordered artifact inventory. The manifest carries no self-digest and no limits member; manifest_sha256 exists only in the five-member sidecar. Signing uses an injected key, and a self-check with an injected verifying key is mandatory.

Number handling is restrictive by contract. The JCS canonicalizer emits minimal ECMAScript formatting for integers and finite doubles, while the manifest and record paths reject f64 and f32 with a typed error: a floating-point value cannot be checked for exact decimal intent from a typed producer input. Exact decimals and wide integers are JSON strings.

Paths accept the ASCII subset of the contract alphabet. Every accepted path is NFC without conversion, and non-ASCII input fails closed, so no ambiguous normalized duplicate can arise.

crate::distribution::ndc_wire is the single canonical wire mapping. This module produces manifest bytes only through that mapping; it owns no second serialization of the manifest.

Publication moves one complete, synced staging directory into its final name with a single no-replace directory rename. Linux uses renameat2(RENAME_NOREPLACE) and macOS uses renamex_np(RENAME_EXCL); other targets fail closed. A durable receipt, not directory presence, is the local acknowledgement. The dated record states the platform bounds.

Each committed transition is one immutable stage record in the ledger. A record binds its sequence number, predecessor digest and canonical bytes; the ledger directory is synced after the record file. That barrier orders process-crash evidence on the declared filesystem. It is not an OS-crash or power-loss qualification (P-D1) until the filesystem is qualified.

Before any release-root change the builder syncs an immutable intent that carries the full artifact inventory, every receipt field and the sidecar digest. Every schema-v2 journal record binds the intent digest. Recovery therefore rebuilds its evidence from the ledger and the release tree; a fresh process needs no heap state from the interrupted publisher. A rename without durable ownership evidence stays quarantined without a receipt.

Non-claim: a signature proves publisher-key control over exact signed bytes. It proves no source authenticity, coverage, right, dataset entitlement or observation truth.
