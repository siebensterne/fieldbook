Module application 

Source
Expand description

Generic source/target reference application (Platform P5).

This module is independent of market-data processing. It demonstrates that the canonical envelope in crate::canonical is reusable by a second, unrelated application: newline-delimited JSON observations in, typed business events out, delivered to a target through an explicit idempotent delivery contract. Nothing here imports or mutates the collector, exchange adapters, order book, SBE writer, raw-frame journal, replay or catalog.

The only shared types are the generic CanonicalEnvelope and the opaque OpaqueId newtype; neither carries market semantics. No driver, live database, network call, wall clock or performance claim is introduced. The PostgreSQL side is a deterministic simulator plus a parameterized SQL contract (see crate::application::postgres).

Delivery is accounted, not assumed. Every receipt is reported in one of six explicit categories, and a non-terminal outcome leaves a DeliveryObligation behind and refuses to advance the committed checkpoint. Replay and dry-run are simulated: they synthesize receipts without touching the wrapped target or the durable store, so a simulated run cannot perform an external side effect or move the durable checkpoint.

Platform P6 adds three additive modules: file_source is a bounded-buffer streaming source with a content fingerprint and a verified resume anchor; durable is a real local append-only checksummed commit store; and the postgres contract gains an executor seam and a transaction transcript. The in-memory JsonlSource remains unchanged.

Enums§

DeliveryReceipt
Delivery receipt. Accepted/Delivered are non-terminal (target accepted, local durability not yet confirmed); DurableCommitted and Rejected are terminal; Uncertain and Outstanding are non-terminal and require a retry with the same idempotency key. Simulated is produced only by dry-run/replay and is terminal for accounting but never advances the durable checkpoint.
DeliveryState
State recorded on a DeliveryObligation. Duplicate is an accounting projection of a committed receipt whose idempotency key was already known.
ExecutionMode
How a run is executed. Only ExecutionMode::Live may write to a target or to the durable store. DryRun and Replay are simulated: no external write and no durable checkpoint progression.
ReceiptCategory
The six report categories of a delivery receipt. Accepted is a legacy non-terminal precursor of Delivered and is reported in the same category.
SourceError
Fail-closed read errors. Each variant carries the evidence needed to account for the rejected line: its sequence, line number and exact bytes.
