Module postgres 

Source
Expand description

PostgreSQL delivery contract and a real synchronous target (Platform P5/P6).

The module keeps the deterministic SQL contract and in-memory PostgresSimulator for offline fault injection, and adds PgTarget, which applies the same SqlExecutor transcript through a real postgres::Client. Migrations are explicit SQL; idempotency is enforced by database uniqueness on the target-specific key; event, disposition and checkpoint writes share one transaction.

The simulator never touches a database. The real target requires an operator-supplied connection and an applied migration; it makes no claim about latency, throughput or absolute zero loss.

One BEGIN ... COMMIT transcript. COMMIT is present only for a terminal durable-commit receipt; a non-terminal receipt leaves the transaction open in the transcript so no caller can mistake simulation for a commit.
CommittedRow

IdempotencyKey
Target-specific idempotency key. The same event delivered to two targets, or under two output contract versions, is a different logical delivery.
ParameterizedStatement
Parameterized SQL text plus bound values. Data is never interpolated into sql; the placeholders $1..$n refer positionally to params.
PgCheckpoint
Checkpoint state owned by the live target between deliveries. last_idempotency_key fences a same-position retry from a different event.
PgExecutor
Execute one statement at a time through a real client and retain affected row counts. A failed statement rolls the transaction back before the error is reported, so a rejected batch cannot leave a partial commit behind.
PgTarget
A real PostgreSQL target. It shares the simulator’s SQL contract and receipts, but executes the transcript against an applied schema. Every delivery carries its source identity, sequence and end offset explicitly; without that position no checkpoint can be advanced.
PostgresSimulator
In-memory PostgreSQL simulator. It is a target, not a database: state is process-local, transactions are deterministic, and nothing is persisted.
PostgresTarget
SQL-generating, receipt-recording facade over the deterministic simulator. Use PgTarget when statements must execute against a real PostgreSQL connection; both targets preserve the same runner and source boundaries.
RecordingExecutor
Deterministic in-memory executor used to exercise the seam offline. It records executed SQL and never touches a database.
