Module durable

Expand description

Real local durable commit store (Platform P6).

This is an append-only, checksummed, fsync-capable store built from the existing atomic JSON helper in crate::report and sha2. It is not the market-data journal and reuses none of its types or formats.

Each commit is a separate, never-rewritten file named commit-<12-digit sequence>.json. One file is one atomic commit unit: it contains the committed event ids, the dispositions and quarantine records, and the new checkpoint, plus a SHA-256 of the exact serialized record. A record is written through write_json_atomic, which writes to a sibling temporary file, fsyncs it, renames it into place and fsyncs the parent directory. On reopen every record is parsed, its checksum is recomputed and the sequence is checked for gaps; truncation, corruption, unsupported schema versions and checkpoint-binding mismatches fail closed.

The store is local and single-writer. It does not provide replication, a database transaction, or a live PostgreSQL connection. The sibling postgres module has a separate opt-in live target; it is not this local commit store and does not change this store’s failure boundaries.

CommitEnvelope
One checksummed file on disk. checksum covers the canonical compact JSON serialization of record only, not the envelope, so re-serializing with a different pretty printer cannot change verification.
CommitRecord
The payload of one atomic commit. All fields live in the same checksummed record, so a partially written commit can never expose a checkpoint without its dispositions, or dispositions without their committed ids.
CommitStore
Append-only local commit store. Every successful commit produces exactly one new checksummed file; nothing is ever rewritten or deleted.
DurableState
Folded, verified state of a commit store after a clean reopen.
StreamingLimits
Hard pull-based bounds for one delivery batch. Batching is bounded by the consumer, never by an unbounded producer queue.
