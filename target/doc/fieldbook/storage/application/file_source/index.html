Module file_source 

Source
Expand description

Streaming file source with bounded I/O buffers (Platform P6).

This is a second source implementation for the non-market-data reference application. Unlike the in-memory JsonlSource, it reads a BufRead one physical line at a time through a fixed-capacity buffer, retains the exact bytes of each line, and reports the physical byte offset of every line. A SHA-256 fingerprint of the complete source bytes is computed once with a fixed-size read buffer, before streaming, so a resume anchor can be bound to the exact content that was originally read. Exact duplicate-id detection uses a bounded-memory, disk-backed hash index: the in-memory state is a fixed-size bucket-head table, and entry chains live in a scratch file that is removed when the source is dropped. No probabilistic filter is used, so a duplicate is reported only after the full identifier matches.

No clock, randomness or network is read. The scratch directory comes from the platform temporary directory; apart from that the module imports only the generic application contract, the opaque identity newtype and the standard library plus serde/sha2. It does not depend on any market-data module or on any storage implementation.

Structs§

CheckpointBinding
The three values a durable checkpoint is bound to: source identity, source fingerprint and target identity. A mismatch on any field invalidates a resume anchor.
DurableCheckpoint
Durable resume anchor. It records the last terminal sequence, its line and its physical byte offset, together with the binding that proves which source bytes and which target it belongs to.
FileSource
A BufRead-backed line source with a fixed-size reusable buffer.
SourceFingerprint
SHA-256 of the complete bytes of a source, computed once before streaming. The text form is sha256:<64 lowercase hex digits>.
SourceIdentity
Registered identity of a streaming source. The id is derived from the registration name only; the fingerprint is derived from the exact bytes. A changed file keeps the same registered id but gets a new fingerprint, which is what makes a stale resume anchor detectable.
SourceRegistry
Explicit registry of named sources. Registration is deterministic: the same name and bytes always yield the same identity.

Hard cap on one physical line. The reader’s reusable buffer never grows beyond this bound plus the single line delimiter, so each physical line is processed with a bounded reusable buffer. Duplicate-id state is separate.
